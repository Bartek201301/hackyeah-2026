# Persistence and access contract

Target schema, not an applied migration. T02 implements additive migrations and records execution in `supabase/APPLIED.md`. Use UUID primary keys, UTC `timestamptz`, integer token/millisecond counters and bigint micro-USD; no floating-point money. Every table has RLS enabled. Organisation IDs and actor IDs come from verified records.

## Tables

Common columns where applicable: `id uuid primary key`, `organisation_id uuid not null references organisations`, `created_at timestamptz not null default now()`. References within an organisation use composite foreign keys `(organisation_id,id)` to prevent cross-org links. Unique `(organisation_id,id)` where referenced.

## Browser RLS matrix

Default deny `anon` everywhere. `authenticated` can SELECT **only** own membership, own deal memberships, and own `actor_activity` with `(select auth.uid()) = actor_id`; membership reads also require active membership. All browser INSERT/UPDATE/DELETE denied. No authenticated SELECT on documents, excerpts, sources, dataset_rows, runs, review, audit base tables, policy/feed base tables, tokens, exports or budgets. Admin routes return safe projections after explicit server checks; being admin does not bypass browser table RLS.

Private Storage buckets `quarantine` and `generated-exports`: no anon/authenticated read/write policies. Gateway service client alone stores/streams objects after authorization. Disable public buckets and public URL generation. Direct browser upload is not used in this bounded demo. Browser Supabase client may support auth and sanitized projections only.

Separate server clients: normal user SSR client for session validation/projections; server-only privileged client for gateway repository operations. Privileged client must never be exported from a client-importable module. RPC execution grants only to service role; revoke public/anon/authenticated execution. For SECURITY DEFINER functions use empty fixed search_path and fully qualified objects; validate actor/org again. RLS alone does not constrain service-role code.

## Atomic RPC responsibilities

- `begin_operation`: validate active membership, record idempotency hash and durable intent, load current control head in one transaction. Existing matching operation returns prior state; conflict returns 409.
- `reserve_call`: lock all relevant org/actor/day buckets in fixed order; include spent + reserved + proposed amounts, lock active-run counter, and reject any exceeded unit. Insert reservations and provider-intent event together. No model call before commit.
- `finish_call`: lock reservation rows; settle exactly once with measured usage. Move reserved to spent, leave unknown units unresolved. Persist provider completion and safe usage projection in same transaction. If actual exceeds reserved record full actual and suspend further calls; do not hide overrun.
- `finalize_run`: persist checked result, terminal event and sanitized projection atomically. Only then expose answer/download.
- `resolve_review`: expected-version CAS, immutable candidate version and approval metadata; publish excerpts only after successful scans and permission validation. Stale candidate returns 409. Review approval is recorded with the actual scanner/policy versions.
- `update_policy` / `update_feed`: validate before transaction, verify expected version, insert immutable next version, update head and audit together. Failed update leaves old head unchanged.

No database transaction encloses an HTTP model call. Intent and completion are separate transactions. Crash after provider start leaves an incomplete operation and unresolved reservation. T03 reconciliation queries bridge call status; no automatic release merely because a lease expired. Admin can conservatively charge reserved amount with reason if usage is permanently unknown; releasing requires positive evidence call never started. Unknown completion cannot produce an answer.

## Queries and indexing

FTS: English `to_tsvector` + `websearch_to_tsquery`, bound query length and result count from policy. Apply org, status and classification/deal filters before ranking and before returning text. GIN on search_vector; B-tree on org/status/classification/deal, memberships actor/org, runs org/actor/created_at and audit trace/created_at. Compound cursor order `(created_at,id)`; `after` ID resolves to an authorised row and selects strictly later rows in descending pagination order. Never reveal cursor existence across users.

Admin aggregate query reads sanitized events/usage by org and time window. Personal aggregates filter actor in SQL, not after loading organisation data. Count distinct root traces separately from subcall decisions. No sensitive source labels in denied-operation projections. Retention is central policy; T12 maintenance only removes expired synthetic raw/export data after team coordination and records the operation. Expiration of a review does not approve it.
