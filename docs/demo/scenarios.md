## Source and import fixture rules

- PUB-01/PUB-02: public annual summary and event notice.
- INT-01/INT-02: internal workbooks, comparable FY2025 revenue disagreement.
- RES-01/RES-02: AsterCloud deal forecasts/bid, analyst-only.
- OTH-01: separate Boreal deal; none of the prepared non-admin accounts has membership.
- MIX-01: useful restricted pipeline fact plus personal contact, synthetic credential and injected instructions. Removing those segments does not make the pipeline fact public.
- REV-01: internal uncertain publication extract. Trusted source registry marks audience evidence unverified; this deterministic ambiguity requires review even if model risk is low. Admin may publish only the independently verified public webinar sentence, citing PUB-02.

CSV upload schema (exact header order): `text,source_date,period,unit,fact_key,basis`. All fields nonempty; text may contain quoted newlines; dates ISO, basis allowlist actual/forecast/proposal/event. The server source record supplies classification, deal and audience_evidence. Those values cannot be set through file content. Cell and total text bounded by policy text limit. Connector payload has these same fields. PDF imports use document-level source metadata from the review form; missing dates/units needed for numeric attribution cause review before publication.

The first excerpt UUID is fixed in each fixture; additional units use deterministic UUIDv5(document UUID, version + locator), recorded in the seed manifest. S04 uses OTH-01 first_excerpt_id, not its document ID. T05 creates one CSV per source and a text PDF containing the same paragraphs; do not ship executable attachments. Expected sanitized MIX-01 candidate is exactly: “Qualified AsterCloud sales pipeline is USD 176 million.” Its classification stays restricted/ASTER. If live assessment cannot establish clean separation, REVIEW is valid and must be demonstrated honestly; unit/integration tests use controlled risk results to verify the REDACT publication branch separately.
