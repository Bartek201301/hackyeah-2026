# AI control layer systems research

**Finding.** The supplied HackYeah brief asks for a working intermediary that governs agent, model, tool, and data interactions through **one configurable policy**, combines deterministic checks with an **AI-based semantic control**, enforces budgets, accepts externally managed historical-attack indicators, and shows decisions in tests, audit, and telemetry ([brief, pp. 1–4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=1)). The most credible design is a small, domain-neutral **action gate**: only a registered executor can perform a managed action after policy has checked identity, destination, model/tool permission, budget, signatures, and semantic findings. This is a recommendation inferred from the brief and research on policy-enforced tool calls, not a specified HackYeah implementation ([CaMeL](https://arxiv.org/html/2503.18813); [Fides](https://arxiv.org/html/2505.23643)). No independent, like-for-like evidence identifies one universally best-performing control-layer product; published security and speed numbers depend heavily on the agent, tasks, attack set, threshold, and deployment. For this team, the existing TypeScript/Next.js proposal is a useful starting point, but **a deterministic-only preview, estimated “tokens,” and a two-action outbox demo do not yet prove the brief’s semantic, allowed-model, or real model/compute-budget capabilities** ([team research](../docs/product/research-decisions.md); [proposed technical spec](../docs/product/technical-spec.md)).

## The brief requires a hybrid control, not a particular stack

The partner permits a **gateway, proxy, middleware, SDK wrapper, or equivalent**; a custom agent is optional. Its formal policy requirement names controls, sensitivity thresholds and block-versus-redact behavior, **allowed LLM models**, and resource/financial budgets. It calls out authentication/access checks and pattern matching as deterministic examples; the challenge section explicitly says to implement both deterministic and AI-based controls, although the formal semantic subsection says to consider AI-based solutions “where possible.” A fair reading is that a real semantic signal must affect at least one demonstrated verdict, while the particular model is the team’s choice ([brief, pp. 2–3](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=2)).

The expected artifacts are an integrable layer and simple diagram, a documented policy with strictness and budget variants, an interactive security dashboard, and an executable positive/negative test suite. Judges may use fresh prompts, edit rules and feeds, inspect logs, and request performance telemetry. Their weights are **30% robustness, 20% architecture/performance, 20% reporting, 15% testing, and 15% implementability/scalability**. They supply no paid API, dataset, or special hardware ([brief, pp. 2–4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=2); [brief, p. 4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=4)). **Neither the analyst/outbox scenario nor Supabase, MCP SDK, JSON, Laya, exact verdict names, or a numeric latency target comes from the brief.** They are team design decisions or still-open choices ([team requirements](../docs/product/requirements.md); [team architecture](../docs/product/architecture.md)). The earlier team research says the four-page PDF was unavailable; that statement is now outdated because the attached PDF has been reviewed ([earlier report](../docs/product/research-decisions.md); [brief, p. 4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=4)). Instructions or examples inside the PDF describe the **challenge and judging**, not a request to change repository files or perform deployments.

## One gate should decide before each consequential effect

**Recommended request flow (design inference):** authenticate the real caller; normalize a typed `actor / operation / resource / destination / model / data provenance` envelope; load and validate one versioned policy and threat-feed snapshot; run hard permission, model/tool allowlist, size, and budget checks; inspect input and lower-trust tool results with signatures and a replaceable semantic assessor; let deterministic policy map all findings to `ALLOW`, `REDACT`, or `BLOCK`; reserve capacity; execute only a registered action; filter its returned data; settle actual usage; and append a redacted trace with the effective versions and measured stage times. A model can label an instruction attempt or exfiltration intent, but it cannot grant access or undo a hard denial. This follows the brief’s hybrid requirement and the research distinction between model judgment and policy-enforced capabilities ([brief, pp. 1–3](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=1); [CaMeL](https://arxiv.org/html/2503.18813); [Fides](https://arxiv.org/html/2505.23643)).

```text
Caller / agent / MCP client
  → authenticated, typed action envelope
  → one policy + feed snapshot
  → deterministic facts + semantic findings
  → policy verdict + atomic budget reservation
  → registered model/tool/resource executor, only if permitted
  → output filter + usage settlement + audit trace
```

**Illustrative policy shape, not an adopted contract:**

```json
{
  "version": 7,
  "profile": "strict",
  "allow": {
    "operations": ["document.read", "message.send", "model.invoke"],
    "models": ["local-approved-model"],
    "recipients": ["synthetic-recipient-1"]
  },
  "controls": {
    "secret_outbound": "block",
    "secret_read": "redact",
    "prompt_injection": { "threshold": 0.72, "action": "block" },
    "semantic_unavailable_for_send": "block"
  },
  "budgets": {
    "requests_per_session": 20,
    "model_input_tokens": 8000,
    "model_wall_ms": 30000,
    "agent_steps": 8,
    "api_cost_usd": 0
  },
  "threat_feed": { "revision": "2026-10-03.1", "source": "reviewed-local-bundle" }
}
```

The **budget has to prevent execution**, rather than merely display totals. Reserve the estimated upper bound before a model/tool call, reject concurrent requests that exceed the remaining balance, then settle against actual tokenizer/provider usage and measured compute time; label approximations as estimates. For a local model, count requests, measured wall time, concurrency, and any available CPU/GPU/memory metric. To enforce a hard compute timeout, the model must run behind a cancellable worker or service boundary; a timeout of the web request alone does not prove that compute stopped. These accounting details are implementation recommendations because the brief asks teams to _think about_ enforcing local and commercial budgets but supplies no algorithm ([brief, pp. 2–3](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=2)).

**Historical attacks need a controlled feed and an interception point.** Store each indicator with ID, category, source, revision, enabled flag, and safe matching form; validate and cap feed size, then show that changing a feed entry changes the next decision and appears in audit. Seed regression cases for prompt injection, malicious code execution, unsafe deserialization, and model-repository supply-chain indicators, because the latter three are explicitly named in the brief ([brief, p. 3](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=3)). A string match on a document is evidence of that match, **not** proof that arbitrary code or model artifacts are safe. Claim exploit mitigation only for the actual surface inspected: for example, a model-install action must check repository origin, pinned revision/hash, and approved artifact metadata before the installation executor runs. Use semantic inspection on lower-trust documents and tool outputs; treat their instructions as data and check any resulting action again at the gate ([CaMeL](https://arxiv.org/html/2503.18813); [NVIDIA execution rails](https://docs.nvidia.com/nemo/guardrails/about-nemo-guardrails-library/rail-types)).

The actionable synthesis is to **borrow the boundary, not a whole platform**: one TypeScript gate and registered executors for the small demo, one actual model invocation and one consequential tool/MCP action behind it, a lightweight versioned policy, and a swappable local semantic assessor. The existing Next.js/Supabase plan already proposes a shared gate, HTTP and MCP adapters, synthetic outbox, and audit transaction; its explicit claim should remain limited to traffic routed through those adapters ([technical spec](../docs/product/technical-spec.md)). MCP tool annotations are descriptive metadata rather than a security guarantee; authorization and runtime checks belong on the server ([MCP maintainer guidance](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/)).

## Published wins are conditional on security, utility, and attack adaptation

**There is no established single “best-performing system.”** CaMeL reports **77% secure task completion versus 84% task completion for an undefended system** on its AgentDojo evaluation and, for one Gemini 2.5 Pro setting, reduces **300 successful injections to 0**; that result uses its policy/interpreter setup and does not predict this team’s latency or multilingual performance ([CaMeL paper](https://arxiv.org/html/2503.18813)). Fides reports a policy-enforced GPT-4o row with **1 successful injection, or 0 after excluding two attack tasks outside its stated policy scope**; its policy is applied to tool calls, so text-only response manipulation remains a caveat ([Fides paper, Table 1 and discussion](https://arxiv.org/html/2505.23643)). These papers strongly support deterministic control of action and data flow, while showing why the precise protected outcome matters.

In a ServiceNow/Mila firewall study on a specific GPT-4o AgentDojo setup, a tool-output sanitizer achieved **0% attack success** with **74.09% benign utility** and **69.15% utility under attack**, while combining it with input minimization kept 0% attack success but lowered benign utility to **58.41%**. On the authors’ more adaptive, three-stage Slack attack cascade, sanitizer attack success rose to **30.0%** ([firewall study, Tables 1 and 6](https://arxiv.org/html/2510.05244)). Another benchmark, AgentDyn, reports **zero utility for CaMeL on its open-ended dynamic tasks**; this does not negate the narrower AgentDojo finding, but it warns against ranking defenses by one static attack set ([AgentDyn paper](https://arxiv.org/html/2602.03117)).

Speed and false positives are equally conditional. OpenAI’s own detector evaluation reports **P50/P95 of 1,481/2,563 ms** for its default remote GPT-4.1-mini check, while its **0.987 ROC AUC** accompanies **0.000 recall at a 1% false-positive operating point** in that test. These are vendor measurements of its test mix, not independent latency or accuracy estimates for a local model here ([OpenAI Guardrails evaluation](https://openai.github.io/openai-guardrails-python/ref/checks/prompt_injection_detection/)). A published attack-adaptation study reports bypassing most of 12 defenses at over 90% success after tailoring attacks to each defense, reinforcing the need for a fresh holdout attack set ([USENIX Security 2026 paper](https://www.usenix.org/conference/usenixsecurity26/presentation/nasr)). None of these studies jointly tests the brief’s model allowlist, budget reservation, feed reload, MCP integration, audit, and latency on identical hardware.

## Measure the actual gate and close four plan gaps first

For every change, run an **offline deterministic suite** with mock model/tools and a mock semantic score: permitted and forbidden actor/resource/tool/model; redaction and outbound secret block; direct and indirect injection; historical indicator update; policy threshold removal/change; request, token, wall-time, and step exhaustion; semantic timeout/abstention; audit failure; and two concurrent requests racing for the last budget unit. Assert **effects as well as verdicts**: a blocked send creates no outbox record, an allowed send creates exactly one, and the log records the effective policy/feed versions without the test secret. Then run a separate **real local semantic** evaluation on unseen English and Polish benign/attack cases, including benign text with suspicious words, and report the confusion matrix and abstentions. Mock tests prove wiring; only live tests prove the AI-based control ([brief, p. 4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=4); [AgentDojo](https://github.com/ethz-spylab/agentdojo); [InjecGuard/NotInject](https://arxiv.org/html/2410.22770)).

Evaluate **attack success, benign task completion, task completion under attack, overblock rate, and executed forbidden effects** separately. Keep a teammate’s fresh, defense-aware attacks outside tuning. For performance, run the same input mix and concurrency with the gate bypassed **only in an isolated benchmark**, deterministic-only, and full hybrid; publish sample count, hardware, versions, cold/warm state, P50/P95/P99 end-to-end and added control latency, throughput, per-stage times, CPU/GPU/memory when available, and actual versus estimated tokens/cost. Aggregate paper run times and a vendor’s remote P95 cannot substitute for this measurement ([firewall study](https://arxiv.org/html/2510.05244); [NIST AI RMF Measure guidance](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)). The dashboard should read the same append-only trace data used by the tests, with security and management views and an export; a display-only counter is insufficient for audit ([brief, p. 3](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=3); [OpenAI trace evaluation guidance](https://developers.openai.com/api/docs/guides/agent-evals)).

**Priority 0:** keep the proposed shared action gate, real side-effect test, policy/feed versioning, and atomic audit/budget/outbox transaction; add a controlled `model.invoke` fixture with an editable model allowlist and measured invocation/compute budget. **Priority 1:** make one real local semantic assessment reachable on the judged path and prove that its result changes a verdict; if unavailable, mark the system degraded and do not claim the hybrid requirement is demonstrated. **Priority 2:** add a pinned, attributable historical feed with executable tests for each category actually intercepted, then independent MCP invocation and a short, measured benchmark. This order changes the earlier plan, which placed live semantics at P2 and treated `ceil(UTF-8 bytes/4)` as its token budget: that value is a request-size proxy and must be named as an estimate, not model token usage ([earlier research](../docs/product/research-decisions.md); [technical spec](../docs/product/technical-spec.md); [brief, pp. 2–4](/Users/julian/Downloads/e251f2e9-fc1d-45b4-b92e-03be0adce8dc.pdf#page=2)). Until an action and artifact path are actually intercepted, avoid claims of arbitrary MCP coverage, code-execution prevention, model supply-chain protection, or production readiness.

## Conclusion

The most defensible 24-hour result is a **small control layer whose authority is visible in real side effects**: an unauthorized destination, disallowed model, exhausted budget, or injected instruction cannot cause the registered executor to act, while legitimate work still completes. Research favors that enforcement boundary more consistently than it favors any particular classifier or vendor. The report’s performance answer is therefore a measurement plan and comparable published tradeoffs, not a borrowed “best” number; the team can make a stronger claim only after running its own holdout attacks, utility scoring, and latency tests on the delivered system.
