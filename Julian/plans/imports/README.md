# Sources and imports — research brief

**Researched:** 2026-10-03. **Scope:** Julian's workbench UI research for T05/G3. **Baseline inspected:** local `40ac062`, merged main `8c1484b` ([G0 PR #5](https://github.com/Bartek201301/hackyeah-2026/pull/5)); no G1 typed client or workbench feature exists yet. This is a contract and usability study, not proof of an ingestion path.

## User outcome and existing contract

An authorized person selects a configured dataset or uploads one CSV/text PDF, sees what can be submitted, then receives a truthful quarantine, processing, approved, partial, review, blocked or failed outcome. Analysts may upload only for assigned deals and their classification is forced restricted; employees and external reviewers cannot upload ([role matrix](../../../docs/product/requirements.md), [T05](../../../docs/team/implementation-plan.md)). Private originals remain quarantined; candidates and excerpts are governed separately from document status ([architecture](../../../docs/product/architecture.md), [data model](../../../docs/contracts/data-model.md)). The MIX-01 demonstration accepts a restricted safe candidate only if separation is actually established; uncertainty legitimately goes to review ([S05](../../../docs/demo/scenarios.md), [AT03](../../../docs/testing/acceptance.md)).

The [OpenAPI contract](../../../docs/contracts/openapi.json) has `GET/POST /api/v1/sources`, `POST /imports/connector`, `POST /imports/upload` and `GET /imports`. Connector submission references an existing `source_id` and `batch_id`, not a caller URL, SQL query or table name. Upload multipart fields are one `file`, `classification`, optional `deal_id` and optional attribution fields in the schema. [Protocols](../../../docs/contracts/protocols.md) add required text-PDF `source_date`, `period`, `unit`, `fact_key` and `basis` through business validation; CSV rows must instead contain the exact six-column header specified in [scenarios](../../../docs/demo/scenarios.md). Import creation returns a run; imports list returns `ImportSummary` with `status` and `classification`. These are separate dimensions and should have separate visible labels.

## Approach findings

| Question       | Evidence-backed direction                                                                                                                                                                                                                                         | Tradeoff to validate after G1                                                                                                                                                                                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File selection | Use a labelled native file input and [FormData](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest_API/Using_FormData_Objects) for multipart transfer through Bartosz's client. Client-side extension, size and metadata hints can prevent mistakes. | The browser's `accept` filter and MIME type are usability hints, not a security check. [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) requires server validation of content/type/size and authorized storage. |
| Limits         | Read active policy's import limits where Bartosz exposes them; the [policy example](../../../docs/contracts/policy.example.json) is only an initial value, not a UI constant.                                                                                     | If the client lacks a safe policy projection, show accepted formats without promising a precise limit until Bartosz supplies one.                                                                                                                               |
| Progress       | Distinguish transfer progress from processing. A plain `fetch`/FormData submit establishes only pending/completed/error at the transfer layer; the run and import list report processing state.                                                                   | Do not claim byte-level progress from elapsed time. If true transfer percentage becomes a requirement, verify the transport/client capability before adding one.                                                                                                |
| Outcome        | Reuse inspected `PageHeader`, `Card`, `Field`, `Input`, `Select`, `Button`, `Notice`, `Badge` and `LoadingState` from shared UI. Render `partial` as a real partial publication with an explicit review or run reference when provided.                           | A table with safe statuses is useful; it cannot expose raw originals, removed segments or private candidate text to the requester.                                                                                                                              |

Native form constraints help users correct missing fields, but [W3C form guidance](https://www.w3.org/WAI/tutorials/forms/validation/) says server validation is still needed. Associate field-specific errors with controls and announce submission/outcome messages ([W3C notifications](https://www.w3.org/WAI/tutorials/forms/notifications/)). The gateway must count bytes, inspect type and content, enforce role/deal/classification, scan complete text and control publication ([technical spec](../../../docs/product/technical-spec.md)); Julian's UI cannot infer safety from a selected filename or a model score.

## States and future evidence

Research states: no configured source; source-list load/error; unsupported or over-limit file before submission; missing PDF attribution; upload pending; accepted but quarantined; processing; approved; partial with safe retained units; review reference; blocked; parser/model unavailable; malformed CSV; encrypted or image-only PDF; run missing after refresh. Expose a reason category only when the server returns one that is safe for this actor. Avoid direct original-download controls.

Future evidence maps to AT03/S05 and AT16: accepted CSV and text PDF; wrong header/order; oversized and chunked payloads; malformed, encrypted, image-only and over-limit-tail PDFs; analyst versus employee/reviewer exposure; direct Storage/PostgREST attempts covered by Bartosz's AT17. Browser QA should inspect keyboard file selection, field errors, status announcements, narrow-screen layout, duplicate submissions, refresh and role switching. The actual ingestion tests and model checks have not run at this baseline.
