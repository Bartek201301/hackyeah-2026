# Public summary and PDF download — research brief

**Researched:** 2026-10-03. **Scope:** Julian's workbench UI research for T09/G3. **Initial baseline:** local `40ac062`, merged main `8c1484b` ([G0 PR #5](https://github.com/Bartek201301/hackyeah-2026/pull/5)). **G1 update:** merged main `f04054b` ([PR #7](https://github.com/Bartek201301/hackyeah-2026/pull/7)) supplies the [workbench entry point](../../../src/features/workbench/index.ts) and generic [typed client](../../../src/shared/contracts/client.ts), while export operations remain 503 unavailable. No PDF or live export was generated during research.

## User outcome and existing contract

Any prepared account can request a fresh public AsterCloud summary and download its checked PDF. The summary must use public-approved excerpts even when the requester is an analyst or admin with wider chat rights. It must not reuse a previous analyst answer or attach an original document ([PRD](../../../docs/product/requirements.md), [architecture](../../../docs/product/architecture.md), [T09](../../../docs/team/implementation-plan.md)). S03 expects only the public FY2025 revenue and webinar notice with citations; internal, restricted and canary values must be absent from the response and PDF text, metadata and attachments ([scenarios](../../../docs/demo/scenarios.md), [AT11](../../../docs/testing/acceptance.md)). Bartosz's gateway owns public-only retrieval, output checking, PDF generation, private storage and download authorization ([technical spec](../../../docs/product/technical-spec.md)).

The [OpenAPI contract](../../../docs/contracts/openapi.json) defines `POST /api/v1/exports` with `topic` and optional `deal_id`; `POST /runs/{id}/execute`; `GET /runs/{id}`; and `GET /exports/{id}/download`. The [protocol](../../../docs/contracts/protocols.md) says export start returns a run, completed export returns `{download_path,expires_at}`, and PDF download returns bytes with `X-Trace-ID` or a JSON error. Mutations require UUID idempotency keys. The download path is an authenticated gateway path, not a public Storage link. Expired, revoked and guessed IDs must be denied server-side ([AT11](../../../docs/testing/acceptance.md)).

## Approach findings

| Question       | Evidence-backed direction                                                                                                                                                                                                                                                                                                                 | Tradeoff to validate after G1                                                                                                                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Start/progress | Use the same governed run lifecycle as chat, displaying safe stage and terminal status. Poll a returned run ID while visible and stop at terminal state ([protocol](../../../docs/contracts/protocols.md)); clean up stale poll responses when the screen changes ([React effect guidance](https://react.dev/reference/react/useEffect)). | An unchecked text preview would be quick to show but would contradict the output-gate requirement.                                                                                                                                                                       |
| Download       | If Bartosz confirms a same-origin cookie-authenticated gateway path, a normal labelled link/button to the returned path is the smallest browser interaction. [MDN's anchor guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a) explains same-origin `download` behavior and browser variations.             | If a typed client must attach extra headers, it may need a Blob download; [MDN advises revoking object URLs](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static) after use. Do not infer that a path is safe to fetch from an arbitrary origin. |
| Readiness      | Show a download control only after completed export and a valid server-returned path/expiry; label expiry and distinguish a completed run from a successful browser file save.                                                                                                                                                            | The UI cannot know whether an export was revoked after rendering; the GET route must enforce that at click time.                                                                                                                                                         |
| Shared UI      | Reuse inspected `PageHeader`, `Card`, `Field`, `Input`, `Button`, `Notice`, `Badge` and `LoadingState`; keep an ordinary browser download affordance accessible by keyboard. [W3C notifications](https://www.w3.org/WAI/tutorials/forms/notifications/) supports clear feedback for completion and errors.                                | Custom PDF preview/rendering adds complexity and can imply access to unchecked or original pages.                                                                                                                                                                        |

The [technical spec](../../../docs/product/technical-spec.md) requires a new public-audience run, only public-approved source versions, validated citations, complete output scan and a fresh PDF with controlled metadata and no attachments/scripts. [OWASP prompt-injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) supports treating source and model text as untrusted until checked. These are gateway responsibilities; the UI's public label is not an access or publication rule.

## States and future evidence

Research states: empty topic; validation error; creating/running; completed and ready; review/blocked with no downloadable file; model/semantic/audit unavailable; incomplete with unknown usage; download 401/403/404; expiry and revocation; interrupted network after request; account switch; successful download through browser. A saved PDF is evidence of transfer, not of public-only contents. Provide an accessible status for readiness/failure ([W3C status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)).

Future evidence maps to S03/AT11/AT16: export as external reviewer and analyst, compare public-only citations; inspect generated PDF text independently plus metadata/attachments; verify guessed ID, expiry and revocation denial; test a refresh and repeated click; check 375 px and 1440 px layouts and keyboard download. Bartosz owns content and access assertions; Julian's browser evidence covers interaction. No export test or PDF evidence exists at this baseline.

## Contract questions and owners

- **Bartosz:** The design asks for visible checked summary text and citations, but completed export response currently specifies only `{download_path,expires_at}`. Will an authorized run/read response expose checked text/citations, or should the workbench show readiness/citations only after another documented call? This needs a coordinated contract decision before a summary preview.
- **Bartosz:** What exact authentication mechanism and origin does `download_path` use? Confirm whether a normal same-origin link is sufficient and which safe error the UI should show on expiry/revocation.
- **Bartosz:** Does the URL ID denote export ID or run ID? OpenAPI's download path says export ID, while the completed run only returns `download_path`; the UI should use the returned path and never derive one.
- **Bartosz + Nikodem:** Which trace route can explain the public-audience decision and selected citation versions without exposing restricted inputs?

**Boundary:** Julian handles topic input, status, checked-data presentation if contracted, and authenticated download interaction. Bartosz owns public-only retrieval, checking, PDF bytes, storage, expiry/revocation and audit; Nikodem owns trace presentation.
