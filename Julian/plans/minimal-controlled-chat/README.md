# Minimal controlled chat — research brief

**Researched:** 2026-10-03. **Scope:** Julian's workbench UI research for T06/G2; no live behavior is claimed. **Initial baseline:** local `40ac062`, merged main `8c1484b` ([G0 PR #5](https://github.com/Bartek201301/hackyeah-2026/pull/5)). **G1 update:** merged main `f04054b` ([PR #7](https://github.com/Bartek201301/hackyeah-2026/pull/7)) now has the [workbench entry point](../../../src/features/workbench/index.ts) and browser-safe [typed client](../../../src/shared/contracts/client.ts); every `/api/v1/*` operation still returns an explicit 503 unavailable response. Recheck later endpoint handoffs before claiming real chat behavior.

## User outcome and existing contract

An authenticated user asks one question and sees safe progress followed by a checked answer with exact citations and a trace link. The analyst may receive assigned-deal material; an employee must not learn restricted deal facts, including through source labels or error text. See [requirements](../../../docs/product/requirements.md), [design](../../../DESIGN.md), [T06](../../../docs/team/implementation-plan.md), [S01/S02/S07/S08](../../../docs/demo/scenarios.md) and [AT06/AT07/AT16](../../../docs/testing/acceptance.md). Single-turn chat, scoped retrieval, answer buffering, citation validation, output assessment and final access recheck belong to Bartosz's gateway, not to the UI ([technical spec](../../../docs/product/technical-spec.md)).

The [OpenAPI contract](../../../docs/contracts/openapi.json) defines `POST /api/v1/chat` with `message` and optional `deal_id`, then `POST /runs/{id}/execute`, `GET /runs/{id}` and `POST /runs/{id}/cancel`. The [protocol](../../../docs/contracts/protocols.md) requires a UUID `Idempotency-Key` on mutations; a new run can return HTTP 202 with no decision. Run states include `pending`, `running`, `completed`, `review`, `blocked`, `failed`, `cancel_requested`, `cancelled` and `incomplete`. A completed chat returns `{answer,citations}`; citation fields include excerpt ID/version, source label/date, period and locator. The UI must not treat 202, `REVIEW`, or a successful transport response as permission to display generated text.

## Approach findings

| Question             | Evidence-backed direction                                                                                                                                                                                                                                                                                                                                                                        | Tradeoff to validate after G1                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Interaction boundary | Keep only the question form and run-status interaction in an explicit Client Component; use the shared typed HTTP client once Bartosz exports it. Installed Next.js 16.3.8 says a `use client` module includes its imports in the browser bundle ([installed guide](../../../node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md)).                         | A wholly client-rendered page is simple but expands the client bundle and makes private data review harder.                                                          |
| Progress             | Render only the server's safe `stage` and run state. Poll the returned run ID at the protocol's one-second interval while visible; stop on terminal state. [React's effect guidance](https://react.dev/reference/react/useEffect) calls for cleanup or ignoring stale responses.                                                                                                                 | A live stream would be more immediate, but the product forbids exposing unchecked generated text.                                                                    |
| Submission/recovery  | Disable repeat submission while pending, retain the operation's idempotency key for a retry, and recover by server run ID rather than replaying execution blindly. Browser abort only stops the local request; it does not prove the server stopped ([MDN AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController), [protocol](../../../docs/contracts/protocols.md)). | Exact reload persistence should follow the G1 client/session handoff; do not store answer or run details in long-lived browser storage by default.                   |
| UI primitives        | Reuse inspected `PageHeader`, `Card`, `Field`, `Textarea`, `Button`, `Notice`, `LoadingState` and `Badge` from `src/shared/ui`. Semantic buttons/links and English labels are already part of [DESIGN](../../../DESIGN.md).                                                                                                                                                                      | The shared `Field` currently wraps label and error text but does not establish an `aria-describedby` link; request a shared change if tests show an association gap. |

[W3C status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) supports announcing short progress/result changes without moving focus. Avoid a noisy live region that repeats every poll; announce meaningful stage changes and the final outcome. Treat generated answer and citations as inert text, with no automatic execution of links or markup; [OWASP's prompt-injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) supports keeping untrusted model output away from privileged actions.

## States and future evidence

Research states: empty question; validation error; creating run; running with safe stage; completed checked answer/citations; `REVIEW` reference with withheld answer; blocked reason without restricted hints; service unavailable; cancellation requested versus confirmed; incomplete with uncertain usage; stale or missing run on reload; account/deal change while a response arrives. `trace_id` exists in the response envelope, but the UI trace destination is Nikodem's feature and Bartosz's app route. Neither route is present at the inspected baseline.

Future tests should inspect S01 analyst citations and the FY2025 conflict, S02 employee non-exposure, S07 attribution, S08 loop stop and zero further calls, and AT07 cancellation/uncertain usage. Browser evidence needs keyboard submission, focus/status announcements, 375 px and 1440 px views, duplicate-submit behavior, refresh and role switching. These are acceptance targets, not executed results; the current repo has no T06 tests or live gateway.

## Contract questions and owners

- **Bartosz:** G1 exports a generic typed `createGatewayClient` and `newIdempotencyKey`, but no operation-specific chat helpers. Should workbench call the typed paths directly, or will Bartosz add helpers? How does a client recover a created run when the create response is lost, without starting a duplicate operation?
- **Bartosz:** Which trusted response supplies allowed deal choices and safe current-user context to the UI? `deal_id` is optional on chat requests, but browser-selected roles and memberships cannot grant access.
- **Bartosz + Nikodem:** What is the stable route for an authorized trace link, and does its URL use the response `trace_id` or a run ID? The two identifiers must not be assumed equal.

**Boundary:** Bartosz owns identity, search/read policy, model/tool execution, buffering, citation validation and audit. Nikodem owns trace presentation. Julian researches/displays only the safe workbench interaction.
